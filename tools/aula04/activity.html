1 · O que você vai construir

Continue no seu projeto Vue. Acrescente um formulário para propor uma melhoria relacionada ao contexto do seu projeto. O formulário deve orientar o preenchimento, rejeitar entradas inválidas e comunicar ao App somente sugestões válidas.

O App deve mostrar quantas sugestões válidas foram registradas nesta sessão e os dados da última sugestão. Preserve os componentes, funcionalidades e personalizações das aulas anteriores.

Seu projeto continua. Trabalhe em lessons/aula-02-vite-vue-componentizacao. Não execute npm create vite@latest e não substitua seu src/ pelo código do professor.

No novo componente

SuggestionForm.vue recebe título e descrição, guarda campos/erros, valida, mostra feedback e emite o evento sugestao com { titulo, descricao }.

No App.vue

Importe e use o componente. Receba o evento, aumente o total de sugestões válidas e atualize a última sugestão. O contador de interesses da Aula 3 permanece separado.

Usuário digita
Formulário valida
Evento leva dados ao App
App atualiza o resumo
Não existe envio à Internet nesta missão. Use uma mensagem como “Sugestão registrada nesta sessão”. Não diga “salvo no banco”, “enviado ao professor” ou “mensagem enviada ao usuário”. Recarregar a página zera esse estado.

2 · Construa por checkpoints

0 — Proteja o trabalho anterior

Faça: execute o app; use git status e git remote -v. Salve o progresso em commit após revisar os arquivos.

Confira: os cartões da Aula 3 funcionam; origin aponta para seu repositório. Não inclua senhas ou dados pessoais de terceiros.

1 — Conecte os campos ao estado

Faça: crie o componente e os rótulos, input, textarea e botões. Use ref e v-model.

Confira: digitar altera os valores que sua função de envio recebe.

2 — Valide antes de registrar

Faça: normalize os valores e aplique as regras de vazio e comprimento.

Confira: título de 4 caracteres e descrição de 14 são rejeitados. Os dois textos ficam disponíveis para correção.

3 — Oriente a correção

Faça: mostre mensagem por campo e sucesso somente no caminho válido.

Confira: corrigir um campo não apaga o outro. Após editar, o sucesso antigo desaparece.

4 — Integre o formulário ao App

Faça: comunique o objeto válido pelo evento e atualize o resumo no pai.

Confira: cada submissão válida soma exatamente 1. Limpar não altera esse total nem os interesses anteriores.

5 — Teste e registre evidências

Faça: execute os cenários da ficha, revise build e código, crie o commit e envie ao seu origin.

Confira: sua ficha identifica entradas, resultado esperado, resultado observado e o commit.

Individualidade: o tema pode ser o da equipe e a base pode ser compartilhada. A implementação avaliada, o commit, as evidências e a explicação desta atividade são individuais.

3 · Ambiente e verificador

Use o ambiente já preparado para a turma. Não troque as versões do package.json ou do package-lock.json por conta própria.

Primeira instalação de course/

Antes: confira origin e upstream no guia do aluno.

1. Baixe o instalador abaixo e salve o arquivo instalar-course.mjs dentro do projeto Vue, na pasta em que estão package.json e src/.

Baixar instalador inicial

2. Nessa pasta, execute:

node instalar-course.mjs

3. Confira a Missão 04 com node course/runner.mjs status. O instalador verifica o repositório do professor, busca somente o pacote permitido e não altera src/, dependências nem remotes. Se já existir course/, ele para e orienta usar update.

É necessário ter Git, Node e acesso ao GitHub nesta instalação. Não execute um instalador recebido de outra origem.

Dois terminais, duas funções

Terminal 1 — manter o aplicativo aberto

npm run dev

Na primeira configuração, instale as dependências com npm ci. Se falhar, registre o impedimento e avise o professor.

Terminal 2 — orientar e verificar

node course/runner.mjs mission 04
node course/runner.mjs check 04

URL padrão: http://127.0.0.1:5173. Se o Vite informar outra porta: node course/runner.mjs check 04 --url http://127.0.0.1:5174.

Para futuras atualizações de materiais: node course/runner.mjs update. Se houver alteração local em course/, a operação é interrompida; não restaure arquivos às cegas.

Checker sem ambiente preparado não dá aprovação. Automação ausente, navegador indisponível ou servidor desligado aparecem como NÃO VERIFICADO. Execute os testes manualmente e anote a limitação. O professor prepara a ferramenta de navegador antes do laboratório.
Seletores neutros para o checker — não mudam seus textos ou estilos

Acrescente data-testid aos elementos abaixo. Exemplo de identificação: <input data-testid="title-input" ...>. Você continua escolhendo nomes internos, mensagens e aparência.
